## Problem Description
Occasionally after a serial connection restart, channel 0 LED remains on and the system outputs rapid identical bogus timestamps:
```
-01.99999970000 chA
-01.99999970000 chA
-01.99999970000 chA
```

## Root Cause (Confirmed via Debug)
Debug output revealed:
```
INTB_A=LOW(ready)         ← Pin physically stuck LOW
INT_STAT_A=0x0            ← But TDC7200 internal status shows NO interrupt
PICstop_A=0:0             ← No STOP pulse was captured
All TDC registers = 0x0   ← TDC returning all zeros (invalid data)
totalize delta = 100      ← Loop spinning at maximum speed
```

**Key Finding**: The TDC7200's INTB pin is physically stuck in the asserted (LOW) state, but the chip's INT_STATUS register shows 0x00 (no interrupt pending). This is a hardware fault condition where the INTB output pin is stuck but the internal state is clear.

## Attempted Fixes (All Unsuccessful)
1. **Soft reset**: Clearing START_MEAS bit and acknowledging interrupts - did not clear stuck INTB
2. **Hardware reset**: Toggling ENABLE pin with various delays (5ms, 20ms, 50ms) - did not clear stuck INTB
3. **Register polling workaround**: Polling INT_STATUS directly bypassing INTB pin - code became too complex and didn't restore functionality
4. **GPIO pin reconfiguration**: Adding `pinMode(INTB, INPUT)` to reset functions - did not clear stuck INTB

## Conclusion
The stuck INTB condition is a true hardware fault that cannot be cleared via software. The condition:
- Survives firmware uploads with serial connection maintained
- Does not respond to ENABLE pin power cycling
- Does not respond to GPIO pin reconfiguration
- Clears **only** with USB power disconnect/reconnect

This suggests the fault is either:
- In the TDC7200 chip's INTB output driver circuit
- In the level shifter between TDC7200 and Arduino
- A latchup condition in one of the ICs that requires full power removal to clear

## Recommendation
**Accept that power-cycle is required to recover from this condition.** The issue is rare and cannot be fixed in software. Users encountering this issue should:
1. Disconnect USB cable
2. Wait a few seconds
3. Reconnect USB cable

This completely clears the condition and allows normal operation to resume.

## Technical Notes
- The issue may indicate a specific failure mode in the TDC7200 chip under certain conditions
- The inconsistency between INTB pin state and INT_STATUS register suggests the fault is in the chip's output driver or internal interrupt logic, not the measurement circuitry
- Future hardware revisions might benefit from an external INTB pull-up resistor or reset circuit, though this is not guaranteed to help
